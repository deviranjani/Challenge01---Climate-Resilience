Request Swim Lane — a chat turn

1. Browser

POST /api/chat with {question, history}. UI renders message, cards (tool results) and followups from the response.

2. FastAPI (api.py)

ChatIn Pydantic model validates length. asyncio.to_thread(service.run, ...) runs the synchronous agent loop off the event loop.

3. service.run()

Fresh AgentContext + InMemorySessionService. Replays history into a session, then drives Runner.run_async.

4. Root agent routing

heat_planner reads prompts.ROOT, calls ADK's transfer_to_agent to one of 3 sub-agents based on the question.

5. Sub-agent → tool

E.g. prediction_analyst calls predict_heat_offset(lat, lon). callbacks.before_tool/after_tool record timing into the trace.

6. Tool → BigQuery

Coverage check, then bq.run_query() with parameters, then ML.EXPLAIN_PREDICT on offset_model. @safe_tool catches any failure.

7. Response assembly

split_followups() extracts the FOLLOW-UPS: line. Response: {message, cards, steps, followups, stopped_early}.

Business Rules Inventory

Validation

Coordinate & range validation

tools/_common.py — validate_coordinates, clamp_int. Every tool validates before building SQL.

Eligibility

Coverage gate

_within_coverage() refuses a prediction outside the measured bounding box — "out_of_coverage", not a guess.

Security

No LLM-built SQL

Every query is fixed text + ScalarQueryParameter; the model only supplies tool arguments.

Security

Exception containment

@safe_tool — no tool exception, and no internal detail, ever reaches the model or the HTTP client.

Routing

Specialist routing

Root prompt routes to exactly one of 3 sub-agents per concern; small disjoint tool sets keep routing unambiguous.

Security

No race/ethnicity reasoning

prompts.py (ROOT, COMMUNITY) explicitly forbids using race/ethnicity to justify a recommendation. See ADR-003.

Eligibility

Step budget

before_model callback stops the loop after AGENT_MAX_STEPS (default 12) rather than looping forever.

Config

Cost ceiling

maximum_bytes_billed (default 1GB) and max_rows enforced on every BigQuery query via Settings.

Cascading rule chain example

Coordinate input → validate_coordinates → coverage check → _within_coverage → if out of coverage, refuse with reason; if in coverage → ML.EXPLAIN_PREDICT → no race reasoning applied to the explanation the agent gives back to the planner.
