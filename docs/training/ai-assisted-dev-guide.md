# AI-Assisted Development Guide

How this team uses AI coding tools in `Challenge01---Climate-Resilience`, written during the
Gold-tier governance bootstrap run on 2026-10-27. Read this before your first AI-assisted PR.

## What AI tools are in play here

- **Claude Code** — the primary governed tool for this repo as of this bootstrap run.
  `CLAUDE.md` is the entry point; `.claude/rules/` holds topic-scoped instructions,
  `.claude/skills/` holds on-demand knowledge packs, `.claude/agents/` holds a custom review
  agent.
- **Google Antigravity (IDE + `agy` CLI)** — set up by the challenge organizers in every
  team's Cloud Shell environment (root `README.md`, "Strongly recommended: Antigravity").
  Used during the original build for ADK boilerplate, BigQuery SQL drafting, and
  Cloud Run deploy scaffolding. Not repo-specific tooling — no dedicated instruction file,
  but it should follow the same rules in `CLAUDE.md`/`.claude/rules/` since it edits the same
  code.
- **ADK's own `adk web`** — not a coding assistant, but worth naming here since it's part of
  the same AI-tooling stack this repo was built with (a local dev UI for the agent, not a
  code generator).

## What's allowed

Any of the above may read, propose, and (with review) write code anywhere in this repo,
subject to:

- Following `CLAUDE.md`'s Instruction Map and the specific `.claude/rules/*.md` spoke(s) for
  the files being touched.
- Never committing a hardcoded secret, API key, or project ID (`.claude/skills/security/SKILL.md`).
- Never reintroducing race/ethnicity as a model feature or reasoning factor
  (`docs/adr/ADR-003-exclude-race-as-model-input.md`).
- Passing `cd agent && .venv/bin/python -m pytest` before a PR that touches `agent/` is opened.

## What gets reviewed

Every AI-assisted change goes through the same review as a human-written one — see
`.claude/skills/review-checklist/SKILL.md`. An AI tool proposing a change does not skip
review; if anything, changes to `agent/heat_planner/prompts.py` (the agent's safety
mechanism: refusal rules, caveats) deserve *more* scrutiny than average, since they're easy
to get subtly wrong while looking correct.

## Available Skills in this repo

| Skill | Use when | Provides |
|---|---|---|
| `security` | adding a BigQuery query, secret, or API key | secret/SQL-injection/cost checklist |
| `review-checklist` | reviewing a PR | this repo's PR checklist |
| `testing` | writing a test | mocking BigQuery with `fake_runner`, driving ADK with `ScriptedLlm` |
| `deployment` | deploying to Cloud Run | deploy command, IAM roles, scaling caveat |
| `database` | writing a query, debugging empty results | `a4i_climate` table/column reference |
| `bigquery-ml-modeling` | changing the offset model's features or prediction tools | `ML.EXPLAIN_PREDICT` usage, feature-set change process |
| `adk-agent-design` | adding a sub-agent or tool | step-by-step for extending the agent tree |
| `monitoring` | debugging a failed request | how to read the tool trace, Cloud Run logs |
